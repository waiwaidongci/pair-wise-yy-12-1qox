# hxyfront-62011 马术蹄铁四蹄测量适配与蹄铁领用台

面向马术俱乐部蹄铁师的四蹄测量、蹄铁适配与领用工作台。

## 业务规则

1. **一马一单**：每匹马同时仅允许一张未结束（非已完成/已留档）适配单，重复开单被拒绝。
2. **缺项不得启动**：四蹄（左前/右前/左后/右后）的长、宽、钉孔距、步态分级任一缺失，核验按钮直接拒绝。
3. **整单核验，任一蹄不过即停在待备料**（库存不扣减）：
   - 蹄长或蹄宽与库存蹄铁差值 **> 2mm**；
   - 钉孔模式不符：孔数不一致或钉孔距差 **> 2mm**；
   - 任一钉位落入**蹄底敏感区**（蹄铁内缘留 10mm 安全余量的椭圆模型，钉深沿蹄支射线方向量入）；
   - 可扣库存不足（同单多蹄使用同一 SKU 合并计算）。
4. **领用扣库**：仅「待领用」单执行领用时按蹄扣减并写出入库台账；沿用旧蹄铁的蹄不扣。
5. **试装双确认**：领用后进入试装，必须由**开单人之外的另一名蹄铁师**确认「步态稳定 + 蹄铁无松动」，**连续两次**才完成；任一次不通过则计数清零重来。
6. **结论失效与留档**：对已领用/试装/已完成单做修正测量、换蹄铁时，旧单状态变为「已留档」并自动开出修正单；修正单默认四蹄沿用旧蹄铁（不重复扣库），改选其他蹄铁的蹄在再次领用时才扣库。
7. **停用库存**：停用蹄铁 SKU 会使引用它的已领用/试装单结论失效（留档 + 自动修正单，数量冻结不扣减）；测量中/待领用单退回测量中重配；已完成历史单不受影响。
8. **刷新一致**：全部状态持久化在 `localStorage`，列表、库存、台账、提醒由同一份状态派生，刷新或多标签页（`storage` 事件）后保持一致。

## 架构（规则 / 持久化 / 界面分拆）

```
src/
├── domain/
│   ├── types.ts          # 领域模型（适配单、四蹄测量、钉位、蹄铁 SKU、台账）
│   └── rules.ts          # 纯函数：缺项校验、2mm 公差、钉孔模式、敏感区几何、
│                         #         状态流转、双确认规则、提醒派生（无 React 依赖）
├── data/
│   └── storage.ts        # localStorage 读写、版本校验、种子数据
├── state/
│   └── store.ts          # useSyncExternalStore 状态容器 + 全部业务动作/台账写入
└── ui/
    ├── App 入口：适配单（列表+详情）/ 库存与台账 / 提醒 三视图
    ├── OrderList.tsx     # 过滤、搜索、缺项与确认进度
    ├── OrderDetail.tsx   # 四蹄卡片、核验/领用、试装双确认、修正、流转留痕
    ├── HoofCard.tsx      # 单蹄测量、选蹄铁（推荐）、钉位表、核验结论
    ├── InventoryView.tsx # 库存、补货、停用/启用、新增规格、出入库台账
    ├── RemindersView.tsx # 待备料/试装/复查/库存提醒
    └── NewOrderForm.tsx  # 新建适配单
```

规则层是纯函数，自检脚本 `scripts/selftest.ts`（46 项断言）覆盖：缺项拦截、一马一单、超差待备料不扣库、钉孔模式、敏感区、领用扣库、他人连续两次确认、修正留档不重复扣库、停用库存失效链。

## 本地运行

```bash
npm install
npm run dev          # http://localhost:62011
npm run build        # 类型检查通过后构建
npx tsc --noEmit     # 仅类型检查
npx esbuild scripts/selftest.ts --bundle --platform=node --format=esm --outfile=/tmp/st.mjs && node /tmp/st.mjs
```

界面内「库存与台账 → 重置演示数据」可恢复内置演示数据（含待备料、试装待确认、复查逾期、钉位入敏感区、已留档修正链等场景）。
